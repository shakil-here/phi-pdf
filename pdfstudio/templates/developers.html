{{ icon('api') }} REST API

no account, no state: send files, get the result

One call per tool: POST {{ base }}/api/v1/tools/<tool> with multipart/form-data: files (one or more), params (a JSON object of the tool's options; plain form fields work too), and image_file / source_file for the watermark picture or the file to insert. The answer is the result file (a ZIP when there are several); the header X-PHIPDF-Summary says what was done. Errors come back as {"error": "…"} with status 400.{% if settings.api_key %} Send Authorization: Bearer <key>.{% endif %}

curl -f -o small.pdf -F files=@big.pdf -F 'params={"level":"high"}' {{ base }}/api/v1/tools/compress
curl -f -o searchable.pdf -F files=@scan.pdf -F 'params={"language":"ben+eng","clean":"strong"}' {{ base }}/api/v1/tools/ocr
import requests   # Python
r = requests.post("{{ base }}/api/v1/tools/merge",
                  files=[("files", open("a.pdf", "rb")), ("files", open("b.pdf", "rb"))],
                  data={"params": '{"bookmarks": "files"}'})
r.raise_for_status(); open("merged.pdf", "wb").write(r.content)

Each tool page has a “Use this from code” box that writes these commands with the options you picked. GET /api/v1/tools lists every tool.

{{ icon('code') }} Command line

phi-pdf                          # open the app on this computer (browser opens)
phi-pdf tools                    # list the tools
phi-pdf run merge a.pdf b.pdf -o out/
phi-pdf run compress big.pdf --set level=high -o out/
phi-pdf run ocr scan.pdf --set language=ben+eng --set output=docx -o out/
phi-pdf run watermark report.pdf --set kind=image --image-file logo.png -o out/
phi-pdf doctor                   # what is installed (OCR, LibreOffice…)
phi-pdf serve --public           # a server for many people (see the README)
